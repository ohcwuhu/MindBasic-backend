# 实验结论与证据边界（提交前必读）

> 用途：对应评分标准里的「技术实现与规范」「完成度与可验证性」。
> 这份文档只做一件事：把**已经跑出来的数字**和**它们能证明的东西**一一对上，
> 并说清哪些结论一旦写出来就属于过度声明。写技术报告和答辩 PPT 时以这份表为准。

## 一、一句话结论

现有材料足以证明三件事：**实现存在**（同一份代码既跑线上也跑实验）、**口径可复现**
（脚本 + 数据 + 结果都在仓库里）、**规则可标定**（阈值与权重都能按数据调整）。

现有材料**尚不足以证明**「真实用户身上的识别准确率」和「阶段化引导确实更好」——
这两件事各自还缺一组真数据（见第三节）。

## 二、结论边界表

| 已有结果 | 它证明了什么 | 它**不能**证明什么 | 引用时必须带上这些限定 |
| --- | --- | --- | --- |
| `experiments/results/fusion_ablation_summary.csv`（动态融合 0.975） | 在 **40 条团队构造样本**上，动态权重优于单模态基线与固定权重；实验与线上共用 `fusion_service.fuse()` 同一条代码路径 | 真实音视频的识别准确率；真实用户的情绪分布 | 「**40 条合成样本**上的消融结果；输入为标注好的模态标签与置信度，**不是真实采集**」 |
| `experiments/results/fusion_ablation_subsets.csv` | 动态权重的增益集中在困难子集（模态冲突 / 面部缺失 / 低置信度 / 短文本） | 这些子集在真实使用中的占比 | 「子集划分为构造样本的划分」 |
| `experiments/results/crisis_eval_levels.csv` | 危机四级规则在 **30 条构造语料**上的分级指标与漏报/误报 | 真实危机识别能力，也不构成任何临床判断 | 「构造语料；规则引擎为模块级常量，可标定」 |
| `experiments/results/stage_agreement_report.md` | 五阶段规则引擎与标注语料的一致性（含逐条不一致分析） | 真实对话里的阶段准确率 | 「标注语料为合成种子（`source` 字段可区分），一致性不等于正确性」 |
| `experiments/results/calibration_*.csv` | 温度缩放能把 ECE 从约 0.42 拉低多少（K 折交叉验证口径） | 校准后的置信度在真实数据上依然可信 | 「**同一批样本内**的校准改善；温度是单调变换，不改变识别结果」 |
| `experiments/results/weight_tuning_report.md` | 网格搜索 + 交叉验证给出的权重与线上经验的差异 | 线上权重应当照搬标定值（样本量不够） | 「标定结果用于说明权重的可调性，不直接替换线上规则」 |
| `experiments/results/coach_ab_blind_sheet.csv` | 两条臂的回复已经生成、盲评表可以发出去（表内已含 8 组对照） | **阶段化引导更好**——`winner_r1` / `winner_r2` / `rationale` 三列当前为空 | 在评分填完之前，**不得**写「A/B 盲评显示…」 |
| `experiments/results/runtime_stats.md` | 运行统计的口径与脚本已经就绪 | 任何延迟、可用性、降级数字（当前窗口内分析记录 **0** 条） | 「口径已就绪，真实样本为 0」 |

## 三、答辩前要补的三组证据

按评审建议的顺序排。每组都写清：要回答什么、怎么取、现在什么状态。

### 1. 真实输入的多模态对比 —— 现状：未采集

- **要回答**：相比只用文本，加入语调与表情在哪些场景有帮助，哪些场景反而会带偏？
- **怎么取**：找 5～10 位同学，各录 3 段真实语音（其中至少一段是「说的话与语气不一致」，
  例如嘴上说「挺好的」但语调低落）；用同一份录音分别跑 `text_only` / `+voice` / `+facial` / `dynamic_weight`。
  权重入口可以直接复用 `experiments/run_fusion_ablation.py` 的 `weights_override`，只换数据源。
- **落点**：`experiments/data/` 新增真实语料目录（并在 `docs/模型清单与许可证.md` 第四节登记来源与授权），
  结果写入 `experiments/results/`。
- **不做的代价**：报告里所有融合数字都只能写成「合成样本上的」，评委会问「真实数据呢」。

### 2. 同模型回复盲评（阶段化引导 vs 普通回复）—— 现状：表已生成、评分列为空

- **要回答**：阶段化引导是否提升相关性、行动可执行性与用户选择权？
- **怎么取**：把 `experiments/results/coach_ab_blind_sheet.csv` 发给 ≥2 位评分者（不要告诉他们 A/B 分别是什么），
  填 `winner_r1` / `winner_r2` / `rationale`；再跑一次 `python experiments/run_coach_ab.py` 汇总。
- **落点**：`experiments/results/coach_ab_raw.csv` 与 `coach_ab_key.json`（评分结束后再对照键）。
- **口径**：样本量小时只报「n 组、k 位评者、倾向」，不报百分点。

### 3. 真实运行记录 —— 现状：窗口内 0 条

- **要回答**：首段回复要等多久；断网、关闭摄像头、模型降级时还能不能继续？
- **怎么取**：跑通若干次真实通话（含一次关摄像头、一次断网重连），然后
  `python experiments/run_runtime_stats.py` 导出；时延明细来自
  `multimodal_analysis_records.timings` 与后端日志。
- **落点**：`experiments/results/runtime_stats.md`（覆盖当前的空窗口版本）。
- **答辩用**：现场演一次「关掉摄像头继续聊」比任何表格都直接。

## 四、必须演示的一个场景：模态冲突

> 用户说「我挺好的」，语调却低落。系统应当**谨慎追问、让用户确认**，
> 而不是直接宣布「你很难过」。

这条能同时展示技术、交互与判断边界，是整套系统里最有说服力的一处细节。

| 环节 | 落点 | 演示时说什么 |
| --- | --- | --- |
| 融合与冲突检测 | `app/services/ai_lab/fusion_service.py`（权重调整 + `conflict` 快照） | 「两种模态不一致时，我们不按多数投票，而是降低结论强度、转成问题」 |
| 风险分级 | `app/services/crisis_rules.py`（四级规则） | 「高风险才升级工单，其余交回对话」 |
| 界面呈现 | `VideoCallPanel.vue` 侧栏的「融合 / 语调 / 文本 / 面部」四行 | 「用户能看到系统依据什么，也能随时关掉语气与表情」 |
| 可复现证据 | `experiments/data/fusion_samples.jsonl` 的「模态冲突」子集；单测 `tests/test_fusion_conflict.py` | 「这一个场景有单测，不是临时演的」 |

**已验证的跑法**：

```bash
cd 项目主体/项目代码/MindBasic-backend
.venv/Scripts/python.exe -m pytest tests/test_fusion_conflict.py -q
.venv/Scripts/python.exe experiments/run_fusion_ablation.py   # 看「模态冲突」子集那一行
```

## 五、写作与答辩口径（三条硬规矩）

1. **合成样本的数字必须带「合成 / 构造 / N 条」**——报告、PPT、答辩口头表述一致；
2. **不裸报数字**：写「在本项目规则引擎与构造语料上，动态权重把整体准确率从 0.925 提到 0.975」，
   而不是「准确率达 97.5%」；
3. **第三方组件与 `docs/模型清单与许可证.md` 保持一致**——不夸大、不隐去。
